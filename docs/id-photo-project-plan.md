# AIPS 项目计划书

## 1. 项目定位

### 1.1 项目名称

证件照智能处理平台（AIPS / AI ID Photo Studio）

当前仓库命名约定如下：

- 主项目：`AIPS`
- 中文名称：`证件照智能处理平台`
- 英文名称：`AI ID Photo Studio`
- 前端子项目：`aips-web`
- 后端子项目：`aips-api`
- 后续管理端命名预留为：`aips-admin`

### 1.2 项目目标

开发一个前后端分离的网站，用户上传一张图片后，可以基于预设规格或自定义参数，对证件照进行真实处理，并导出符合要求的最终文件。

这里的“真实处理”指的是：

- 真正改变图片像素宽高
- 真正改变图片裁剪范围
- 真正改变图片分辨率元数据（DPI）
- 真正改变图片文件大小、压缩率、格式
- 真正执行锐化、模糊、亮度、对比度等图像算法

它不是前端视觉预览层面的“看起来变了”，而是后端生成了一张新的、参数已经被实际修改过的图片文件。

### 1.3 典型使用场景

- 考研报名证件照处理
- 专升本报名证件照处理
- 教资考试证件照处理
- 高考报名证件照处理
- 求职简历证件照处理
- 一寸、二寸、三寸、四寸等常规规格照片处理
- 用户自行输入宽高、单位、文件大小要求进行处理

### 1.4 核心价值

- 替代用户反复使用 PS 进行重复性证件照处理
- 降低证件照处理门槛
- 提高处理效率
- 提供标准化规格预设
- 支持真实导出可提交的成品文件

## 2. 项目范围

### 2.1 MVP 范围

第一阶段只做最核心、最有价值的能力：

1. 上传图片
2. 选择预设证件照规格
3. 自定义尺寸和单位
4. 裁剪和缩放
5. 清晰度增强或降低
6. 修改格式、DPI、压缩质量、文件大小
7. 处理前后预览
8. 下载导出

### 2.2 第二阶段扩展能力

- 背景颜色替换
- 人像自动居中
- 人脸区域比例校正
- 批量处理
- 历史记录
- 登录/订单/付费
- 管理后台维护规格模板

### 2.3 暂不纳入第一阶段

- 类似 Photoshop 的通用图层编辑
- 蒙版、钢笔、通道、复杂修图
- AI 换装、AI 美颜、AI 生成头像
- 多人协作编辑

## 3. 需求分析

### 3.1 用户流程

1. 打开网站
2. 上传原始照片
3. 选择预设规格或自定义规格
4. 调整裁剪框、位置、缩放比例
5. 设置输出参数
6. 点击处理
7. 查看预览结果
8. 下载最终图片

### 3.2 核心功能清单

#### A. 图片上传

- 支持 JPG、JPEG、PNG
- 限制最大文件大小，例如 10MB
- 上传后显示原图尺寸、文件大小、格式
- 校验图片是否损坏

#### B. 规格预设库

- 内置常用证件照模板
- 支持分类展示
- 每个模板包含：
  - 名称
  - 宽高
  - 单位
  - DPI
  - 背景色要求（可选）
  - 文件大小要求范围（可选）
  - 格式要求（JPG/PNG）

预设示例：

- 一寸
- 二寸
- 三寸
- 四寸
- 考研报名
- 专升本报名
- 教资报名
- 高考报名

#### C. 自定义尺寸

- 支持输入宽、高
- 支持切换单位：
  - 像素 px
  - 毫米 mm
  - 厘米 cm
  - 英寸 inch
- 支持设置 DPI
- 根据单位和 DPI 自动换算像素

换算公式：

- inch = cm / 2.54
- inch = mm / 25.4
- pixel = inch * DPI

#### D. 裁剪与缩放

- 前端显示裁剪框
- 支持拖拽图片位置
- 支持缩放
- 固定目标比例
- 支持居中辅助线
- 支持“适配”与“填充”两种模式

说明：

- 适配：保证整张脸尽量完整，可能留白
- 填充：严格填满目标画布，可能裁掉边缘

#### E. 图像调整

- 亮度调整
- 对比度调整
- 饱和度调整
- 锐化
- 模糊
- 降噪（第二阶段也可）

其中“清晰度增强”建议第一阶段先定义为“锐化增强”，而不是宣传成超分辨率。因为超分辨率属于另一类 AI 能力，成本和复杂度明显更高。

#### F. 输出控制

- 输出格式：JPG、PNG
- 输出 DPI
- 输出质量 quality
- 文件大小控制
- 文件名自定义

文件大小控制支持两种模式：

1. 指定上限，例如“不超过 200KB”
2. 指定范围，例如“100KB 到 200KB”

#### G. 处理结果预览

- 原图与处理后图片对比
- 展示处理后尺寸、格式、DPI、大小
- 支持重新调整后再次处理

#### H. 下载导出

- 点击下载处理后的图片
- 支持导出标准文件名
- 可选导出处理参数说明

## 4. 业务规则

### 4.1 关于“尺寸”的真实含义

很多证件照平台其实会同时校验以下参数：

- 像素尺寸
- 宽高比例
- 文件大小
- 图片格式
- 有时会读取 DPI 元数据

因此系统处理时，不能只改显示区域，必须真正生成新图片。

### 4.2 关于“文件大小控制”

文件大小不是简单写死的，它通常受到以下因素影响：

- 图像像素总量
- 图片内容复杂度
- 输出格式
- JPEG 压缩质量
- 色彩采样方式

因此后端应通过迭代压缩来逼近目标大小，而不是一次性固定质量值。

推荐策略：

1. 先完成裁剪和尺寸变换
2. 输出为目标格式
3. 如果用户设置了大小要求，则对 JPEG 质量进行二分查找
4. 直到文件大小落入目标范围或达到允许误差

### 4.3 关于“清晰度增强”

第一阶段推荐采用传统图像算法：

- Unsharp Mask
- Sharpen kernel
- Contrast enhancement

这是可控、成本低、部署简单的方案。

如果后续要做“照片变清晰很多”，那已经进入 AI 超分辨率方向，建议第二阶段单独做。

### 4.4 关于单位换算

用户输入厘米、毫米、英寸时，最终必须转换成像素后再进行实际处理。

例如：

- 3.5cm x 5.3cm
- DPI = 300

换算：

- 宽度像素 = 3.5 / 2.54 * 300 = 413 px
- 高度像素 = 5.3 / 2.54 * 300 = 626 px

最终以整数像素输出。

## 5. 技术方案建议

### 5.1 前端技术栈

推荐：

- Vue 3
- TypeScript
- Vite
- Pinia
- Vue Router
- Element Plus
- Cropper.js 或自定义裁剪组件

推荐 Vue 3 的原因：

- 适合快速搭建交互型表单界面
- 组件拆分清晰
- 国内生态资料多
- 与前后端分离项目配合成熟

### 5.2 后端技术栈

推荐：

- Python 3.11+
- FastAPI
- Pydantic
- Pillow
- OpenCV
- NumPy
- Uvicorn

可选扩展：

- MediaPipe：做人脸检测和自动构图
- Celery + Redis：后续做异步任务
- SQLAlchemy + PostgreSQL：后续做模板管理、用户记录

### 5.3 为什么后端选 Python

这是合理选择，原因如下：

- Python 图像处理生态成熟
- Pillow 适合常规图片读写、缩放、裁剪、压缩
- OpenCV 适合图像增强、滤波、边缘处理、人脸检测
- 开发速度快
- 便于后续接入 AI 图像能力

### 5.4 Photoshop 底层是否也是 Python

不是。

Photoshop 这类软件的核心通常由 C/C++ 实现，并配合 GPU 加速、图形管线和大量工程优化。它们底层调用的是高性能图像算法，不是 Python 本身。

但是，你要做的网站不需要复制 Photoshop 的底层架构。对于“证件照处理”这个场景，Python 调 Pillow 和 OpenCV 已经足够做出真实可用的系统。

## 8. 后端核心处理流程

### 8.1 处理流程

1. 接收上传图片
2. 读取原图元信息
3. 校验输入参数
4. 计算目标像素尺寸
5. 根据前端传来的裁剪区域裁切原图
6. 执行缩放
7. 执行亮度/对比度/锐化/模糊等增强
8. 设置输出格式和 DPI
9. 如果有文件大小要求，则迭代压缩
10. 输出最终文件
11. 返回处理结果地址和元信息

### 8.2 关键算法说明

#### A. 裁剪

输入：

- 原图尺寸
- 裁剪框坐标
- 缩放比例

输出：

- 裁剪后的目标区域图像

#### B. 缩放

使用高质量重采样算法，例如：

- Lanczos
- Bicubic

#### C. 锐化

可使用：

- Pillow 的 `ImageFilter.UnsharpMask`
- OpenCV 的卷积核锐化

#### D. 模糊

可使用：

- Gaussian Blur

#### E. 文件大小控制

适用于 JPG：

- 通过 quality 参数多次压缩
- 二分法逼近目标区间

如果是 PNG，则文件大小控制能力较弱，因为 PNG 是无损格式，主要适合透明背景或高保真导出。

## 9. 接口设计草案

### 9.1 获取预设规格

`GET /api/v1/presets`

返回：

- 规格列表

### 9.2 上传图片

`POST /api/v1/files/upload`

返回：

- file_id
- 原图宽高
- 原图大小
- 原图格式

### 9.3 处理图片

`POST /api/v1/images/process`

请求示例字段：

```json
{
  "file_id": "xxx",
  "preset_id": "kaoyan_2026",
  "custom_size": {
    "width": 3.5,
    "height": 5.3,
    "unit": "cm",
    "dpi": 300
  },
  "crop": {
    "x": 120,
    "y": 60,
    "width": 800,
    "height": 1200,
    "scale": 1.0
  },
  "adjustments": {
    "brightness": 0,
    "contrast": 0,
    "saturation": 0,
    "sharpness": 20,
    "blur": 0
  },
  "output": {
    "format": "jpg",
    "dpi": 300,
    "quality": 90,
    "target_size_kb_min": 100,
    "target_size_kb_max": 200,
```

返回：

```json

    "size_kb": 156
```

`GET /api/v1/health`

## 13. 风险与难点

### 13.1 难点一：不同考试平台要求不统一

同样叫“证件照”，不同平台可能要求不同：

- 宽高不同
- 大小限制不同
- 背景色不同
- 是否要求近期免冠不同

解决方案：

- 用“预设模板”机制管理规格
- 后续做可维护的模板后台

### 13.2 难点二：文件大小精确控制

严格命中某个大小区间并不容易。

解决方案：

- 对 JPG 使用质量二分法
- 设置误差容忍范围
- 超限时给出建议

### 13.3 难点三：前端裁剪坐标和后端真实裁剪要一致

这是实现中最容易出错的地方之一。

解决方案：

- 明确前端显示尺寸和原图实际尺寸的映射关系
- 统一坐标换算规则
- 写单元测试验证裁剪结果

### 13.4 难点四：用户说的“清晰”未必等于算法上的清晰

有些用户想要的是“增强锐度”，有些用户想要的是“AI 修复”。

解决方案：

- 第一阶段只做传统锐化
- UI 上准确命名为“锐化增强”
- AI 超分辨率单独列为未来版本

## 14. 推荐开发顺序

建议严格按下面顺序推进：

1. 先做后端图片处理核心能力
2. 再做前端上传和参数输入
3. 再对接裁剪交互
4. 再做预览和下载
5. 最后做模板管理和体验优化

原因：

- 这个项目的核心价值不是页面，而是后端图像处理能力
- 如果算法链路先没跑通，前端做再漂亮也没有意义

## 15. 验收标准

一个合格的第一版，至少应满足：

1. 用户上传一张图后，能选择一个证件照规格
2. 能裁剪并输出指定像素尺寸
3. 能设置 JPG/PNG 输出
4. 能设置 DPI
5. 能做锐化或模糊
6. 能把 JPG 压到指定大小范围
7. 能下载真实生成的图片
8. 下载后的图片参数经本地查看工具验证是正确的

## 16. 结论

这个项目完全可行。

从工程实现上看，它不是在“模拟 Photoshop”，而是在“围绕证件照场景，把 PS 里最常用的一小部分能力产品化”。

如果目标是先做一个真实可用的版本，那么最合理的路线是：

- 前端：Vue 3 + TypeScript
- 后端：FastAPI + Pillow + OpenCV
- 第一阶段只聚焦上传、尺寸、裁剪、锐化、压缩、导出

这条路线开发成本可控，技术风险低，而且能较快做出一个可演示、可验证、可继续扩展的版本。
